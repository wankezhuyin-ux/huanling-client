# 命名体系 v1 · 以画喻武

> [!] **本文已被 v2 取代，仅作历史留档。**
> v1 用画法术语（匀息描 / 罩染功 / 逆锋 / 皴 / 澄浆 / 东舣），玩家看不懂，已全部作废。
> 现行方案见 `docs/命名对照全表.md`（可搜索版 `命名对照全表.html`），落地脚本：
> `tools/apply_names_v2.py`（道具/武学/技能/套装）、`tools/apply_map_names.py`（地图）。
>
> v2 标准只有两条：**字都是常用字，词都是玩家听过的词**。水墨感靠意象，不靠术语。


> 《墨境》的命名总纲。世界上的一切都用**一支笔、一张纸、一池墨**来解释：
> 武功是笔法，丹药是颜料，地图是画境，宠物是墨生灵兽。
> 这样玩家不需要看文案也能感觉到"这是一款讲水墨的游戏"，而不是给老游戏换了层皮。

## 一、总原则

1. **一条内核**：凡力量皆有笔法对应（提按、中锋、侧锋、飞白、破墨、皴擦）。
2. **可猜**：名字要能让玩家猜出效果方向（防御类用"罩/固/护"，攻击类用"劈/破/焦"）。
3. **不撞**：不用任何真实作品名、门派名、人物名、名画名、现代商标。
4. **键不动**：物品**内部 id 一律不换**，只换 `name` 显示字段。
   - 背包、邮件、交易、帮派仓库存的是 id；换 id 会让老玩家东西变"未知物品"。
   - 换皮换的是玩家看得见的字，不是数据库里的钥匙。

### 这一批顺带建好的迁移机制

道具的**名字就是存档 id**，改名必须带迁移，否则老玩家的书会变成「未知物品」。
现在这条链路是通的，后续 275 个道具、148 张地图改名都能直接复用：

| 环节 | 位置 | 做法 |
|---|---|---|
| 改名表 | `deploy/server/data/item-rename.json` | 旧名 md5 前 8 位 → 现用名，磁盘不留明文旧名 |
| 服务端读档 | `core.py` `State._migrate_item_names()` | 扫背包 / 仓库 / 邮件附件，命中即换名 |
| 客户端读档 | `game_data.gd` `migrate_item_name()` | `InventoryItem` 建对象时归一，背包/仓库/交易全覆盖 |
| 白名单 | `client-item-names.json` | 由 `tools/rename_pet_skills.py` 从 `ALL_ITEMS` 重建 |
| 自检 | `tools/check_item_consistency.py` | 道具键 / 白名单 / 迁移表 / 武学池 四表对齐 |

已实测：往存档里塞一本旧名的书，重新读档后背包、仓库、邮件三处都自动变成新名，
而「小还丹」这类没改名的物品不受影响。
